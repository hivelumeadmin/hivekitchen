## Story

As a **HiveKitchen developer**,
I want to **introduce a deterministic `OnboardingController` that owns the interview state machine via per-moment slot predicates over the Kitchen Map + `onboarding_moment_state`, advancing the moment the instant required slots are satisfied — by reading state, not parsing `[NEXT_MOMENT:]`**,
so that **the interview's control flow lives in one deterministic, testable place (no LLM mock needed), replacing the fragile sentinel-plus-safety-net design and setting up `s7` to delete the safety nets entirely**.

---

## Acceptance Criteria

**AC1 — Per-moment slot predicates defined.**
- Required slots are defined as predicates over the Kitchen Map projection + `onboarding_moment_state`, e.g.:
  - M1 (`m1_table`): `household_name` set AND ≥1 child declared.
  - M2 (`m2_safe`): an `allergen_response` recorded per child (the required safety gate).
  - M5 (`m5_starting_line`): starting-line complete per the Epic 2.6 gate.
  - Plus M3/M4 and the `summary`/finalize-eligibility predicates matching the current required-set (`m1_household_name`, `m1_child_declared`, `m2_allergen_response`, `m5_complete`).

**AC2 — Controller owns transitions.**
- `OnboardingController` advances `current_moment` the instant required slots are satisfied, reading state — NOT parsing `[NEXT_MOMENT:]`. Forward-only ordering preserved (`MOMENT_ORDER`, `onboarding.service.ts:267`).
- In this slice the controller runs alongside the existing path (shadow / authoritative-for-transitions) so behavior can be compared; the LLM-led sentinel path and safety nets are NOT yet deleted (that's `s7`).

**AC3 — `household_name` swap is slot-derived (the `s5` deferral).**
- The M1 `household_name` hint-chip swap is implemented as a function of slot state (kids declared AND household_name empty → household-name hints), replacing the `[CHIP_PROMPT:household_name]` sentinel path.

**AC4 — Controller is testable without an LLM.**
- Controller transition tests run with **no LLM mock at all** — feed slot states, assert the resulting moment + chip config. This testability is the headline maintainability win.

**AC5 — Safety nets are mapped, not yet deleted.**
- Each existing safety net (M3/M4 chip auto-advance `:956`/`:979`, kitchen-map-inference re-anchoring `:929`, `pre_start → m1_table` fallback) is mapped to a named slot predicate with a transition test, so `s7` can delete the safety net and rely on the predicate. The predicates must reproduce the safety nets' outcomes (verified by the `s1` eval safety-net scenarios).

**AC6 — Resume / reset reconstructs from slot state.**
- Resume/reset mid-interview reconstructs `current_moment` from slot state (covered by existing `onboarding.service.test.ts` resume/reset cases, which must still pass).

**AC7 — No DB schema change (verify).**
- Slot predicates read existing `onboarding_moment_state` + the Kitchen Map projection. If any predicate needs a column not already present, surface it explicitly (not anticipated — verify and document).

**AC8 — Behavior preserved.**
- The `s1` golden eval stays green — the controller's transitions/slot-fills/tool-calls match the captured baseline.
- A shadow-run (old LLM-led path vs new controller path on the same transcripts) shows parity before this slice is marked done.
- Existing onboarding tests green; root typecheck clean.

## Dev Notes

### Why this slice exists

This is the core of the re-architecture. Today the LLM owns the FSM (emits `[NEXT_MOMENT:]`) and the service compensates with safety nets when the LLM forgets — the flow lives in two places (prompt + safety nets) that must agree. The planner already learned this lesson (3.5-s5 single-shot collapse deleted its `MAX_PLAN_ITERATIONS` loop + stopped-without-compose fallback). Here a deterministic controller reads slot state — which is already the source of truth via the Kitchen Map — and advances the moment when required slots are filled. This slice introduces the controller and proves equivalence; `s7` then deletes the LLM-led path. Splitting it this way keeps each step shadow-verifiable behind the `s1` eval and `s3` trace.

### Patterns to follow

- **`MOMENT_ORDER` + `parseMomentKey` (`onboarding.service.ts:267-290`)** — forward-only ordering semantics to preserve.
- **The required-set gate (`finalizeTextOnboarding`, `:1499-1539`)** — the authoritative spec for finalize-eligibility slots.
- **Planner single-shot collapse (3.5-s5)** — the precedent for replacing an LLM-driven loop with deterministic control, shadow-verified by a golden eval.
- **`s3` trace dir** — use it to capture per-turn controller-vs-sentinel mismatches during the shadow phase.

### Anti-patterns to avoid

- **Do not** delete the safety nets or sentinel parsing in this slice — that's `s7`, after parity is proven. This slice is additive + shadow.
- **Do not** let the controller call the LLM or read the DB directly — it's a pure function of passed-in state (keeps AC4 testability and honors the "DB access via API only, never from agent layer" invariant).
- **Do not** introduce a DB column without surfacing it (AC7) — the brief expects none.
- **Do not** change finalize to auto-commit — finalize stays explicit (user tap); the predicate gates *eligibility* only (carried into `s7`).

### Edge cases captured in the brief

| Edge case | AC | Handling |
|---|---|---|
| Safety net rescues a missed transition today | AC5 | Map each to a named predicate + test; eval safety-net scenarios prove equivalence |
| Resume / reset mid-interview | AC6 | Reconstruct moment from slot state |
| A predicate needs missing data | AC7 | Surface explicitly; none anticipated |
| Controller diverges from current behavior | AC8 | `s1` eval + shadow-run gate before done |

### Project Structure Notes

- New controller module under `apps/api/src/modules/onboarding/` (e.g. `onboarding.controller.ts`) — pure, no I/O.
- Slot predicates read the Kitchen Map projection + `onboarding-moment.repository.ts` state (passed in).
- No migration expected (AC7).

### Testing Standards

- Controller: pure unit tests, no LLM mock (AC4).
- Service: existing `onboarding.service.test.ts` (transitions, required-set, resume/reset) must stay green.
- Eval: `2.7-s1` golden set is the parity gate.

  `OnboardingSlots` slot model + `MOMENT_SLOT_PREDICATES` (the named per-moment exit
  predicates, AC1). Three methods:
  - `nextMoment(current, slots)` — forward-only slot-driven advance through the spine
    (AC2); promotes `pre_start → m1_table` (the pre_start fallback), caps at `summary`,
    never steps backward.
  - `reconstructMoment(slots)` — rebuilds `current_moment` from slots when there is no
    prior moment row (AC6); reproduces the kitchen-map re-anchoring safety net, which
    **skips the optional M3** when M1+M2 are already satisfied (lands on M4).

- **`onboarding.service.ts` (MOD)** — surgical:
  - Removed the `HOUSEHOLD_NAME_HINT_CHIPS` const (moved into the controller) and the
    `householdNameChipRequested` sentinel detection (AC3). The `[CHIP_PROMPT:household_name]`
    text strip is **kept** (the prompt still emits it until s7 rewrites the prompt) so it
    never leaks to the user.
  - Added a single shared `controller` field. Inside the post-turn moment block (after the
    `upsertState`), assembled `controllerSlots` from the freshly-computed required-set +
    the M3/M4 chip-answered signals (same signals the safety nets read), then SHADOW-RAN
    the controller (`reconstructMoment` when no prior row, else `nextMoment`) and logged any
    divergence. **The controller is not yet authoritative for the write — that is s7.**
  - Replaced the sentinel chip swap with `controller.chipConfig(...)`.

**AC1 slot model.** `m1HouseholdName`, `m1ChildDeclared`, `m2AllergenResponse`, `m5Complete`
map 1:1 onto the existing required-set (`finalizeTextOnboarding` gate is the finalize-
eligibility spec). `m3Answered`/`m4Answered` carry the optional-moment "answered" signal

**AC5 safety-net → predicate map (each has a transition test in `onboarding.controller.test.ts`):**
- M3 chip auto-advance → `nextMoment(m3_taste, {m3Answered:true}) === 'm4_bag'`.
- M4 chip auto-advance → `nextMoment(m4_bag, {m4Answered:true}) === 'm5_starting_line'`.
- kitchen-map re-anchoring → `reconstructMoment({m1,m2 done}) === 'm4_bag'` (M3 skipped).
- `pre_start → m1_table` fallback → `nextMoment('pre_start', empty) === 'm1_table'`.

**AC7 — no DB schema change.** The controller reads only passed-in state (Kitchen Map
projection + `onboarding_moment_state` required-set). No predicate needs a column that

**AC8 — shadow-run parity (analytic, over the 9 s1 golden scenarios).** The controller
reproduces the live moment sequence on **8/9** scenarios turn-for-turn (spine, m3-elevation-
strict, safety-net-chip-only, safety-net-reanchor, pre-start-bootstrap, resume-in-progress,
reset-interview, finalize-gate-negative). The one divergence is **`m5-cold-start` turn 1**:
the recorded LLM directive jumps `pre_start → m5_starting_line`, **skipping the M2 safety
wall**; the controller (reading slots — no allergen response recorded) reconstructs
`m2_safe` and refuses to skip. This is a genuine shadow finding that validates the
inversion thesis: deterministic control will not skip the safety gate. It is LOGGED (not
failed) in this slice; when s7 makes the controller authoritative, the `m5-cold-start`
golden's directive-driven skip will be corrected (out of scope here). The s1 eval stays
green because the live path remains authoritative for the write.

**Parity-safety of the one live change (AC3).** Audited every golden's captured
`lastTurn.chip_config`: only `pre-start-bootstrap` ends on a `hint` config, and there
`m1ChildDeclared` is false (turn 1, no child yet) so the swap does not fire — the golden is
unchanged. No scenario's captured last turn lands on `m1_table` with a child declared and
no household name, so no golden moved.
