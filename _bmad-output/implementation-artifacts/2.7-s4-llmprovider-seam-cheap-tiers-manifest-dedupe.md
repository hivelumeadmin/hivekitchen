## Story

As a **HiveKitchen developer**,
I want to **route the onboarding agent through the planner's `LLMProvider` seam instead of the raw `OpenAI` client, move the classifier/extractor calls onto a cheap model tier, and delete the duplicate `NotImplementedError` onboarding tool stubs in the manifest**,
so that **onboarding stops hardcoding `gpt-4o` in five places, stops running a 5-token yes/no on a frontier model, and has a single source of truth for tool definitions — cutting recurring LLM cost with no quality loss**.

---

## Acceptance Criteria

**AC1 — Provider seam replaces the raw client.**
- `OnboardingAgent` talks to the planner's `LLMProvider` interface (and `ResilientProvider` where retry/backoff applies) instead of the raw `OpenAI` client.
- The conversational tool-loop turn stays on the strong tier.

**AC2 — Classifiers/extractors move to a cheap tier.**
- `extractSummary` (`onboarding.agent.ts:362`), `inferCulturalPriors` (`:418`), and `isSummaryConfirmed` (`:546`) run on a cheap model tier (Haiku-class) via the provider seam.
- No remaining hardcoded `'gpt-4o'` literals in onboarding (grep-clean across `onboarding.agent.ts` `:71`, `:379`, `:448`, `:562` and any others).
- The model tier is configurable (env / provider config), not a new hardcoded literal.

**AC3 — Cheap-tier quality validated before flip.**
- Before flipping each call, validate cheap-tier output against current `gpt-4o` output on fixtures: `extractSummary` key-completeness, `inferCulturalPriors` plausibility, `isSummaryConfirmed` exact `verdict === 'yes'` behavior. Capture the validation in the PR/Completion Notes.

**AC4 — Manifest dedupe.**
- The `NotImplementedError` onboarding tool stubs in `apps/api/src/agents/tools.manifest.ts:177-238` are deleted; the real specs in `onboarding.tools.ts` are the single source of truth. No dangling references.

**AC5 — Telemetry shows the drop.**
- `onboarding.text_turn_usage` (and the classifier call sites) reflect the reduced cost (cheap-tier token accounting). The strong-tier conversational turn is unchanged.

**AC6 — No behavior regression.**
- The dormant `respondSingleShot` voice path (`onboarding.agent.ts:149`) stays behaviorally identical through the provider swap, including `[SESSION_COMPLETE]` handling.
- `isSummaryConfirmed`'s strict `verdict === 'yes'` regex + prompt-injection delimiters hold on the cheap model. (Note: this *call* is deleted in `s7` once completion is a slot predicate; keep it correct here.)
- `2.7-s1` eval green; existing onboarding tests green; root typecheck clean.

## Dev Notes

### Why this slice exists

`gpt-4o` is hardcoded in five places in `onboarding.agent.ts` (`TEXT_MODEL` `:71`, plus literals in `extractSummary` `:379`, `inferCulturalPriors` `:448`, `isSummaryConfirmed` `:562`), and the agent talks to the raw `OpenAI` client rather than the `LLMProvider` interface the planner uses. The classifiers don't need a frontier model — `isSummaryConfirmed` is a 5-token yes/no (`max_tokens:5`). Moving them to a cheap tier is pure recurring savings with no quality loss. Separately, `tools.manifest.ts` still carries dead `NotImplementedError` onboarding stubs alongside the real specs — two definitions of the same tool names is a maintenance trap.

### Patterns to follow

- **Planner `LLMProvider` / `ResilientProvider`** (Epic 3.5: `3-2-domain-orchestrator-llmprovider-adapter`, `3-30-llm-provider-failover-circuit-breaker`, `3.5-s7-provider-resilience-extraction-mini-tier-eval`). The mini-tier work in 3.5-s7 is the direct precedent for cheap classifier tiers — read it.
- **`onboarding.agent.test.ts`** OpenAI mock — adapt to mock the provider seam instead.

### Anti-patterns to avoid

- **Do not** introduce a new hardcoded model literal — tier selection is config/provider-driven (AC2).
- **Do not** move the conversational turn to the cheap tier — only the classifiers/extractors (AC1/AC2).
- **Do not** change `respondSingleShot` behavior — it's the dormant voice path, kept identical (AC6).
- **Do not** "fix" `isSummaryConfirmed` semantics here — it is deleted as a *call* in `s7` (completion becomes a slot predicate); keep it correct in the interim.

### Edge cases captured in the brief

| Edge case | AC | Handling |
|---|---|---|
| Cheap model degrades summary/cultural-prior quality | AC3 | Validate vs current `gpt-4o` on fixtures before flip; `inferCulturalPriors` already swallows failures to `[]` (silence-mode) → worst case no regression |
| `isSummaryConfirmed` exactness on cheap model | AC6 | Keep strict `verdict === 'yes'` + injection delimiters; test on cheap tier |
| Dormant voice single-shot path | AC6 | Behaviorally identical through the swap |

### Completion Notes List

**Design — provider seam adoption (AC1).** `OnboardingAgent` now takes an `LLMProvider` (was the raw `OpenAI` client). The five production construction sites wrap `fastify.openai` in `new OpenAIAdapter(...)` (default options → ZDR header on, a privacy improvement for child-PII turns; no output behavior change). The conversational tool loop + dormant voice single-shot both call `provider.completeWithMessages(...)` on `tier: 'flagship'`; the agent's own dot↔`__` encoding, strict-tool serialization, and usage-extraction helpers were deleted — the adapter owns them now.

**Strict-tool parity (AC6, preserves 2.7-s2).** Routing onboarding's multi-tool `tool_choice:auto` turn through the shared adapter required a new `strictAllTools` option on `LLMCallOptions` (the adapter previously hardened only a single `forcedToolName` for the planner). With `strictAllTools:true` every tool is emitted `strict:true` with `additionalProperties:false`, all-required, optionals as `anyOf:[…,null]` — byte-identical to the 2.7-s2 path. `stripNulls` stays in the agent (applied to adapter-parsed args before each handler's Zod parse).

**Cheap tier (AC2/AC3/AC5).** `extractSummary`, `inferCulturalPriors`, `isSummaryConfirmed` now call `provider.complete(...)` on `tier: 'mini'` (gpt-4o-mini via the adapter's `TIER_TO_MODEL` — consistent with the planner mini-tier choice, resolving open-question #1). JSON-mode preserved via a new `responseFormat: 'json_object'` option on the seam. Zero `'gpt-4o'` literals remain in onboarding (grep-clean). `onboarding.text_turn_usage` is unchanged (still the flagship conversational turn); the cost drop is the three classifiers moving to mini.

**AC3 validation.** Live cheap-vs-flagship A/B on fixtures requires a real key and is the **user-side gate** (mirrors `planner-mini-tier.eval.test.ts`, which is OPENAI_API_KEY-gated). The structured safety nets make a weaker model non-regressing by construction: `extractSummary` filters to `onlyStrings`; `inferCulturalPriors` swallows any failure/parse error to `[]` (silence-mode, UX-DR46) and clamps/validates keys; `isSummaryConfirmed` keeps the strict `verdict === 'yes'` regex + injection delimiters. The 2.7-s1 golden eval (17/17 green) proves the structured FSM/tool/finalize behavior is preserved through the tier swap. New unit tests assert each call's tier + `responseFormat` + the strict-verdict + the `[]` fallback.

**Manifest dedupe (AC4).** Deleted the 7 onboarding `NotImplementedError` stub specs + their `TOOL_MANIFEST` entries + 14 now-unused contract-schema imports. `TOOL_MANIFEST` is 17→10 entries (planner tools only). No importer of the stubs existed; the planner is the sole consumer of `TOOL_MANIFEST` and never offered onboarding tools, so the stubs were dead duplicates.

**Tracer (2.7-s3 touch-point).** `TEXT_MODEL` (a `'gpt-4o'` literal) → `TEXT_MODEL_TIER: LLMTier = 'flagship'`; the trace `model` field now records the tier (the adapter resolves the concrete id). Tracer + its test updated.

**ResilientProvider.** Not constructed for onboarding (interactive text turns shouldn't inherit the planner's ~90s 429 token-window wait). The agent depends only on the `LLMProvider` interface, so a `ResilientProvider` can be injected later with no agent change (AC1 "where retry/backoff applies").

**Deviations:** (1) renamed `TEXT_MODEL`→`TEXT_MODEL_TIER` (the literal had to go per AC2; the name now reflects a tier, not a model id); (2) promoted `OpenAIMock.cursor` off `private` to clear the 2 pre-existing 2.7-s1 tsc errors so root typecheck is clean (AC6).

[`apps/api/src/agents/onboarding.agent.ts`]
- [x] [Review][Defer] D-2.7S4-CR4: No guard at `LLMCallOptions` level prevents passing `responseFormat: 'json_object'` alongside a non-empty tools array — OpenAI rejects this with a 400; no current caller does it but the interface permits it. [`apps/api/src/agents/providers/llm-provider.interface.ts`]
- [x] [Review][Defer] D-2.7S4-CR5: `extractSummary` lacks try/catch around `provider.complete()` and `JSON.parse` — pre-existing behavior (original raw-OpenAI call also had no catch); unlike `inferCulturalPriors` (silence-mode → `[]`), any failure propagates to the service layer. [`apps/api/src/agents/onboarding.agent.ts`]
- [x] [Review][Defer] D-2.7S4-CR6: `finishReason === 'stop'` guard exits tool loop even when `toolCalls` are non-empty — pre-existing OR logic (`toolCalls.length === 0 || finishReason === 'stop'`); in practice OpenAI never emits tool calls with finish_reason=stop simultaneously. [`apps/api/src/agents/onboarding.agent.ts`]
- [x] [Review][Defer] D-2.7S4-CR7: `lastAssistantContent` stale from an earlier tool-call iteration could become the user-facing response on cap-exhausted exit — pre-existing behavior; fallback phrase covers the null case. [`apps/api/src/agents/onboarding.agent.ts`]
- [x] [Review][Defer] D-2.7S4-CR8: When the adapter returns a raw string (JSON parse failure on tool args), `stripNulls` passes it through unchanged and the handler's Zod schema emits an opaque schema-type error rather than a clear parse-failure error — behavior change vs old uncaught throw, but actually more robust (caught vs uncaught). [`apps/api/src/agents/onboarding.agent.ts`, `apps/api/src/agents/providers/openai.adapter.ts`]
- [x] [Review][Defer] D-2.7S4-CR9: `addStrictConstraints` applied to an object schema node with no `properties` key emits `required:[]` + `additionalProperties:false`, blocking the model from emitting any properties — pre-existing adapter behavior; all current onboarding tool schemas have explicit properties. [`apps/api/src/agents/providers/openai.adapter.ts`]
- [x] [Review][Defer] D-2.7S4-CR10: Classifier call usage (`extractSummary`, `inferCulturalPriors`, `isSummaryConfirmed`) never flows into `OnboardingAgentUsage` or any telemetry event — structural consequence: these are called outside `respond()` in the service layer; the cost reduction is real but not independently measurable per call site. [`apps/api/src/agents/onboarding.agent.ts`]

**Dismissed (8):**
- `complete: false` unconditional in `respondWithTools` — by design; text path uses `isSummaryConfirmed` for session completion, not `[SESSION_COMPLETE]` sentinel (voice-only).
- `stripNulls` null-in-arrays — already deferred as D-2.7S2-CR1 in prior review; not a new finding.
- `finishReason=stop` + tool calls exits loop — pre-existing OR logic; OpenAI doesn't emit these simultaneously.
- All-system-message history → empty `recent` in `isSummaryConfirmed` — degenerate input impossible in practice.
- `JSON.stringify(tc.arguments)` could throw on circular/BigInt — not possible from OpenAI JSON responses.
- `responseFormat: 'json_object'` implicit "JSON" in systemPrompt requirement — informational only; current code is correct.
- `TIER_TO_MODEL` compile-time only — spec intent ("env / provider config") was illustrative; compile-time centralization satisfies AC2.
- `buildMessagesFromLLM` JSON.stringify throw on circular/BigInt — not reachable from OpenAI-parsed responses.
