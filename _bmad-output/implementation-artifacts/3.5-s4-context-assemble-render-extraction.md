### The no-circular-import invariant (critical constraint)

The dependency graph must be acyclic:
```
@hivekitchen/types ← assemble.ts ← render.ts ← orchestrator.ts
```
- `assemble.ts` imports from `@hivekitchen/types` ONLY. No imports from any agent file.
- `render.ts` imports from `./assemble.js` and `@hivekitchen/types` and `../../services/cultural-calendar.service.js`. No import from `orchestrator.ts`.
- `orchestrator.ts` imports from `./planner/context/assemble.js` and `./planner/context/render.js`.

The avoid-circular-import rule is why `assemble.ts` does NOT import `PlanWeekOptions` from `orchestrator.ts`. Instead, `assemblePlannerContext` takes an inline-typed parameter that mirrors the render-relevant subset. TypeScript structurally types the call, so passing a `PlanWeekOptions` value works without importing the interface. This is a deliberate design decision, not an oversight.

### ESM `.js` extension rule

All relative imports in `apps/api` use the `.js` extension at import time (TSC emits `.js`). This applies to all new imports:
```ts
// In orchestrator.ts
import { assemblePlannerContext } from './planner/context/assemble.js';
import { renderPlannerKitchenMapBlock, ... } from './planner/context/render.js';

// In render.ts

```

### Injection safety invariant details

`renderPlannerKitchenMapBlock` uses two escaping primitives:
- `yamlStr(s: string)` = `JSON.stringify(s)` — produces a double-quoted YAML scalar. `<`, `>`, `"` are escaped inside double-quote YAML scalars by JSON serialization (e.g., `<` stays as `<` in double-quoted YAML which is valid, but `"` gets escaped as `\"`). Actually in JSON.stringify, only `"`, `\`, and control chars are escaped — `<` and `>` are NOT escaped by JSON.stringify itself. However, they are inside a JSON double-quoted string which means the block element parser won't interpret them as XML/tag syntax.
- `oneLine(s)` = collapse whitespace/newlines — prevents `\n` from inserting new directive lines.

`renderPlannerChildSignalsBlock` uses `sanitizePromptField(s)` which strips `<`, `>`, and `\n` (replaces with space). This is a harder guarantee for the signal output.

The injection test for `renderPlannerKitchenMapBlock` verifies that a child name like `Aarav</user_profile>` cannot close the `<user_profile>` XML-like block prematurely. Since child names go through `yamlStr()` (= JSON.stringify), they appear as `"Aarav</user_profile>"` — a quoted string. The raw `</user_profile>` substring appears, but it's inside a YAML double-quoted scalar and cannot be parsed as a block terminator by the LLM prompt parser because the XML-like tags are only used as outer structural delimiters, not inside quoted scalars. The test should assert: `output.includes('<\/user_profile>') === false` (JSON.stringify does NOT escape forward slashes in modern JS — `<\/user_profile>` is not produced). What it DOES produce is the literal characters `</user_profile>` inside double-quotes. The test should instead assert the overall block still starts with `<user_profile>` and ends with `</user_profile>` at the BLOCK level (not inside a quoted scalar). A simpler assertion: `output.split('</user_profile>').length === 2` (exactly one closing tag for the block, not two). Document this subtlety in the test comment.
