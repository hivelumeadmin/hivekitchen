## Story

As a **HiveKitchen developer**,
I want to **make the LLM a stateless turn function, delete the prose sentinels and the service-side safety-net heuristics (and the `isSummaryConfirmed` LLM call), and split the ~950-line `submitTextTurn` into `OnboardingController` + `TurnRunner` + a thin service**,
so that **onboarding stops being fragile: control flow is deterministic and tested without an LLM, per-turn LLM calls drop to ~1 (from up to 6+1), and the god method is gone — completing the re-architecture that mirrors the planner's**.

---

## Acceptance Criteria

**AC1 — LLM becomes a stateless turn function.**
- The conversational LLM call is reduced to: `(current moment, kitchen-map state, user message) → converse + fill slots via tools`. It no longer decides control flow.
- The directive instructions for `[NEXT_MOMENT:]`, `[CHIP_PROMPT:]`, and `[SESSION_COMPLETE]` are removed from `apps/api/src/agents/prompts/onboarding.prompt.ts`.

**AC2 — Sentinels and safety nets deleted.**
- Deleted from `onboarding.service.ts`: `[NEXT_MOMENT:]` parsing (`:828`), residual `[CHIP_PROMPT:]` handling, M3/M4 chip auto-advance (`:956`/`:979`), kitchen-map-inference re-anchoring (`:929`), and the `pre_start` fallback — all now subsumed by the `s6` controller's slot predicates.
- The `isSummaryConfirmed` **LLM call** (`:1385`) is deleted; completion eligibility is the slot predicate from `s6`.
- The deleted safety-net tests are **removed, not skipped**.

**AC3 — `submitTextTurn` decomposed.**
- `submitTextTurn` (`:468-1417`) is split into:
  - `OnboardingController` (FSM + slot predicates, from `s6`),
  - `TurnRunner` (assemble prompt → call provider → execute tools → trace),
  - a thin service (thread bookkeeping only).
- No single method approaches the former ~950-line size; responsibilities are separated and independently testable.

**AC4 — Per-turn LLM-call count drops to ~1.**
- Telemetry (`onboarding.text_turn_usage`) confirms a typical turn makes ~1 LLM call (2 only when a tool result must shape the reply), down from 1–2 + a separate classifier call once history ≥ 6. Pure-chip turns remain zero-call (from `s5`).

**AC5 — Finalize stays explicit.**
- Finalization remains **never-auto** (explicit user Finalize tap; prompt `:296-297`). The slot predicate gates *eligibility*, not auto-commit.

**AC6 — Voice single-shot path resolved.**
- The dormant `respondSingleShot` voice path's `[SESSION_COMPLETE]` handling is either kept (if still genuinely used) or removed with the rest. Confirm usage and document the decision.

**AC7 — Behavior preserved, then de-risked cutover.**
- The `2.7-s1` golden eval is green and the shadow-run shows parity BEFORE the LLM-led path is removed (cutover order: prove parity → delete).
- Full Epic 2.5 + 2.6 onboarding E2E suite green; existing service/tool/contract tests green (minus the intentionally-removed safety-net tests); root typecheck clean.

## Dev Notes

### Why this slice exists

This completes the inversion. With the controller (`s6`) proven equivalent, the compensating machinery is now dead weight: the prose sentinels, the safety-net heuristics, the `isSummaryConfirmed` round-trip, and the ~950-line `submitTextTurn` god method (`:468-1417`) that mixes thread I/O, chip resolution, the FSM, catalog side-effects, cold-start logic, and telemetry. Deleting them and splitting the method is what makes onboarding stop being fragile and brings the per-turn call count to ~1. This mirrors the planner's 3.5-s5 (single-shot loop collapse) + 3.5-s4 (context assemble/render extraction) endgame.

### Patterns to follow

- **Planner 3.5-s4 (context assemble/render extraction) + 3.5-s5 (single-shot loop collapse)** — the precedent for lifting assembly/orchestration out of a god method into pure modules and deleting the compensating loop, proven by the golden eval. Read both records.
- **The `s6` controller** — owns the FSM; `TurnRunner` must not re-implement transition logic.
- **`TurnRunner` shape** — assemble → call provider (`s4`) → execute tools → trace (`s3`); mirror the planner's orchestrator/turn separation.

### Anti-patterns to avoid

- **Do not** delete anything before parity is proven (AC7 / Task 1) — cutover order is prove-then-delete.
- **Do not** skip the obsolete safety-net tests — delete them (AC2). A skipped test reads as "still covered."
- **Do not** make finalize auto-commit (AC5) — eligibility ≠ commit; the explicit Finalize tap stays.
- **Do not** leave a partial god method — if any responsibility can't be cleanly extracted, surface it rather than leaving a 500-line residue.
- **Do not** alter the dormant voice path's behavior if it's still used (AC6) — keep it identical or remove it cleanly.

### Edge cases captured in the brief

| Edge case | AC | Handling |
|---|---|---|
| Finalize must not auto-fire | AC5 | Slot predicate gates eligibility; explicit tap commits |
| Voice single-shot `[SESSION_COMPLETE]` still used? | AC6 | Confirm usage; keep identical or remove with the rest |
| Deleting safety nets re-opens a transition | AC2/AC7 | `s6` predicates (stricter, state-derived) + `s1` eval safety-net scenarios prove preservation |
| Cutover regresses behavior | AC7 | Prove parity (eval + shadow) BEFORE removing the LLM-led path |
