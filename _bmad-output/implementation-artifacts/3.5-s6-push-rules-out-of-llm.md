### AC2 — `applyPlanDefaults` — fills defaults without overwriting explicit values

`applyPlanDefaults` returns a new `PlanComposeTreeOutput` (never mutates the input). It walks every `day.slots[].variations[]` and fills in defaults for any field the model left `undefined`:

| Field | Default | Source |
|---|---|---|
| `portion_size` | `'regular'` | Constant |
| `spice_level` | `'mild'` | Constant (safe choice per prompt §spice) |
| `texture` | Derived from child's `age_band` | `ctx.kitchenMap?.children` |

**`texture` derivation rule:**
```
age_band 'toddler'              → 'soft'
age_band 'child' | 'preteen' | 'teen' → 'normal'
child_id not found in kitchenMap.children → 'normal'   (safe fallback)
ctx.kitchenMap undefined        → 'normal' for all children  (safe fallback)
```

**Constraint — allergen-fork preservation:** `removals`, `add_ons`, `cutting_style`, `container`, `notes`, and `paused_at` are NEVER modified. The function touches only the three default fields, and only when they are `undefined`.

**Return shape:** Structurally identical to `PlanComposeTreeOutput`. The function returns a new object with the filled-in variations; the top-level `plan_id`, `household_id`, `week_of`, `prompt_version`, `main_assignments`, `reasoning`, `variant_proposal`, and `degraded_reason` fields pass through unchanged.

### AC3 — `enforceNoConsecutiveMain` — deterministic no-consecutive-Main validator

`enforceNoConsecutiveMain(output)` walks `output.days` and throws if adjacent consecutive calendar days share the same Main.

**Algorithm:**

```
WEEKDAY_ORDER = ['monday','tuesday','wednesday','thursday','friday','saturday']

1. Sort output.days by WEEKDAY_ORDER index.
2. For each adjacent pair (prev, cur) in the sorted list:
   a. If WEEKDAY_ORDER.indexOf(cur.day) - WEEKDAY_ORDER.indexOf(prev.day) !== 1:
      → skip (non-consecutive gap, e.g. Mon→Wed).
   b. prevMain = prev.slots.find(s => s.slot_kind === 'main')?.main_assignment_sequence
   c. curMain  = cur.slots.find(s => s.slot_kind === 'main')?.main_assignment_sequence
   d. If prevMain === undefined || curMain === undefined:
      → skip (day has no main slot — paused or extra-only day).
   e. If prevMain === curMain:
      → throw Error(
           `[enforceNoConsecutiveMain] consecutive Main on ${prev.day}→${cur.day} (sequence ${prevMain})`
         )
3. Return without throwing if no violations found.
```

**Edge cases:**
- **1-day plan:** no adjacent pair exists → returns without throwing.
- **2-day non-consecutive plan (e.g. Mon + Wed):** delta = 2 → skipped → no throw.
- **2-day consecutive plan (Mon + Tue) with same main:** delta = 1 → throws.
- **Paused/extra-only day:** `main_assignment_sequence` undefined → the pair is skipped, not flagged.
- **D-3S33-CR3 (2-day sequence ambiguity):** For a 2-day plan with sequences 3 and 5 (non-1..2): validator only compares sequences for adjacency, so sequences 3 and 5 on Mon+Tue → different → passes. Sequences 3 and 3 on Mon+Tue → same → throws. The validator does NOT enforce sequence contiguity (that is D-3S33-CR3's pre-existing open concern, out of scope for s6).

### `applyPlanDefaults` implementation sketch

```ts
const TEXTURE_BY_AGE_BAND: Record<AgeBand, 'soft' | 'normal'> = {
  toddler: 'soft',
  child: 'normal',
  preteen: 'normal',
  teen: 'normal',
};

export function applyPlanDefaults(
  output: PlanComposeTreeOutput,
  ctx: PlannerContext,
): PlanComposeTreeOutput {
  // Build a lookup map from child_id → age_band for O(1) per-variation access
  const childAgeBandMap = new Map<string, AgeBand>(
    ctx.kitchenMap?.children.map((c) => [c.id, c.age_band]) ?? [],
  );

  return {
    ...output,
    days: output.days.map((day) => ({
      ...day,
      slots: day.slots.map((slot) => ({
        ...slot,
        variations: slot.variations.map((v) => {
          // Derive texture default from age_band; fallback to 'normal' when
          // the child is unknown (unknown child_id or no kitchenMap).
          const ageBand = childAgeBandMap.get(v.child_id);
          const textureDefault = ageBand !== undefined ? TEXTURE_BY_AGE_BAND[ageBand] : 'normal';
          return {
            ...v,
            portion_size: v.portion_size ?? 'regular',
            spice_level: v.spice_level ?? 'mild',
            texture: v.texture ?? textureDefault,
          };
        }),
      })),
    })),
  };
}
```

The `??` (nullish coalescing) pattern ensures existing explicit values are preserved. Only `undefined` gets a default.

### `enforceNoConsecutiveMain` implementation sketch

```ts
const WEEKDAY_ORDER = [
  'monday', 'tuesday', 'wednesday', 'thursday', 'friday', 'saturday',
] as const;

export function enforceNoConsecutiveMain(output: PlanComposeTreeOutput): void {
  const sorted = [...output.days].sort(
    (a, b) => WEEKDAY_ORDER.indexOf(a.day) - WEEKDAY_ORDER.indexOf(b.day),
  );

  for (let i = 1; i < sorted.length; i++) {
    const prev = sorted[i - 1];
    const cur = sorted[i];

    const prevIdx = WEEKDAY_ORDER.indexOf(prev.day);
    const curIdx = WEEKDAY_ORDER.indexOf(cur.day);
    if (curIdx - prevIdx !== 1) continue; // non-adjacent gap — skip

    const prevMain = prev.slots.find((s) => s.slot_kind === 'main')?.main_assignment_sequence;
    const curMain = cur.slots.find((s) => s.slot_kind === 'main')?.main_assignment_sequence;
    if (prevMain === undefined || curMain === undefined) continue; // no main slot — skip

    if (prevMain === curMain) {
      throw new Error(
        `[enforceNoConsecutiveMain] consecutive Main on ${prev.day}→${cur.day} (sequence ${prevMain})`,
      );
    }
  }
}
```

### Why `enforceNoConsecutiveMain` throws rather than corrects

A deterministic correction algorithm (e.g. swap the second day's main with the next available sequence) would cascade: fixing day[i+1] might create a new violation at day[i+2]. A repair loop is more complex code and hides model drift. Throwing instead:
- Surfaces violations immediately in dev/CI (the eval catches them; the golden fixtures never violate the rule)
- In production, the error propagates to the BullMQ job's unhandled-error handler → retry with a fresh compose call (same behavior as any other compose-layer error)
- The golden-eval harness's `assertNoConsecutiveMain` already guards that our stubbed fixture responses don't produce violations; if a future fixture does, the eval fails before the validator even runs

This is the same philosophy as the `plan.compose` step-10 throw (s5, AC2): fail loud and fast rather than silently patch.

## Review Findings

_Code review 2026-06-25 (bmad-code-review). 3 layers: Blind Hunter, Edge Case Hunter, Acceptance Auditor. Acceptance Auditor confirmed AC1–AC7 all PASS; the recorded prompt-pinning test deviation is justified._

- [x] [Review][Decision→Dismissed] `enforceNoConsecutiveMain` silently passes a malformed day array — DISMISSED: duplicate weekday entries are impossible given `PlanComposeTreeOutputSchema` validation runs before this function; model outputs one entry per weekday by construction. Gap A (duplicate days) and Gap B (multiple main slots) are both unreachable in the current flow. — Now that the prompt prose is trimmed, this validator is the hard gate. But (a) two days that share the same weekday produce `curIdx - prevIdx === 0`, so the `!== 1` guard `continue`s and two same-Main Mondays are never compared (`post-compose.ts:83`); and (b) `.find(s => s.slot_kind === 'main')` checks only the FIRST main slot, so a day with two different Mains is reduced to its first (`post-compose.ts:85-88`). `PlannerDayInputSchema` bounds slot count and cross-checks sequences but does not forbid duplicate weekdays or multiple main slots per day (`packages/contracts/src/plan.ts`). Decision: is one-main-per-weekday guaranteed upstream (then the validator no-op is acceptable), or should the validator harden against malformed day arrays? (source: blind+edge)
- [x] [Review][Defer] Local `WEEKDAY_ORDER` copy can silently drift from `WeekdaySchema` [post-compose.ts:16-23] — deferred, latent. `indexOf` returns `-1` for any weekday not in the hand-maintained local list. Cannot trigger today (the compose-output enum is mon–sat, a strict subset of `WEEKDAY_ORDER`), but if `WeekdaySchema` ever gains `sunday`, a sunday day sorts to `-1` and `monday(0) - sunday(-1) === 1` falsely flags Sun+Mon as adjacent while a real Sun→Mon gap is mis-evaluated. The decoupling from the canonical schema list is intentional (no test-helper cross-import) but unguarded. (source: blind+edge)
