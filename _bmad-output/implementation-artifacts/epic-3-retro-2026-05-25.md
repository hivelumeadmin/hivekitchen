## What Went Well

### 1. Review sharpness compounded across the epic
The single biggest win (Menon's call). Early reviews (3-23: 2 patches) grew to 3-27 (7 patches) and 3-29 (9 patches) — but the *quality* of findings improved more than the count. By 3-27 the team was catching concurrent race conditions in sovereignty toggle, ARIA role gaps, and idempotency key issues that would have been missed earlier. The deferred-work log used as a living in-epic reference made each successive review more informed — reviewers could pattern-match against prior stories.

### 2. Explicit dependency sequencing held
3-31 (Recipe Agent) shipped before 3-23 and 3-24, as planned. This was a deliberate call under time pressure and it held. No shortcuts. The sprint-status `# SHIP FIRST` annotation was respected.

### 3. Hard-fail vs degraded separation is architecturally clean
Hard-fail writes to `audit_log` (source of truth for ops); degraded state writes to `brief_state.plan_state`. Different data sources, different recovery paths. Ops visibility via `GET /v1/plans hard_fail` field. The distinction matters for Epic 9 dashboards and the separation was maintained across all stories that touched it.

### 4. Allergy guardrail remained deterministic outside the agent boundary
Every story from 3-23 through 3-27 touched the guardrail boundary. Not once did a change make the agent responsible for safety outcomes. The architectural invariant held.

### 5. False-positive dismissal discipline
40+ findings dismissed rather than acted on means real findings got signal. Reviewers trusted their own judgment more as the epic progressed. The deferred-work log is honest — it carries real deferrals, not rubber-stamped dismissals.

## What Didn't — Recurring Friction

### 1. `planWeek()` signature proliferation
Was 6 positional params at 3-18. Each story added one: 3-22 (7), 3-23 (8/11), 3-24 (12). Each time the options-object refactor was deferred because the story scope made touching the signature feel risky. By the end of the epic the test harness was passing 6 args to a mock of an 11-12 param function — green tests not testing the real signature. Reached critical mass.

### 2. Cross-story contract change without alignment check (FALCPA ⚠️ SAFETY)
Story 2.6-s7 renamed guardrail engine canonical allergen keys (plural → singular: `eggs` → `egg`, `milk` → `dairy`, etc.). Correct for the engine. But the onboarding M2 chip keys still emit the old plural forms. Result: a child declared allergic to `'eggs'` via onboarding has `allergen: 'eggs'` stored; `FALCPA_SYNONYMS['eggs']` returns undefined; mayo, albumin, meringue are not checked. The safety net (deterministic guardrail evaluating at plan time) partially mitigates — but only for items that pass through `evaluate()`. Surfaced by 3-24 review; flagged ⚠️ SAFETY in deferred-work.md. Root cause: 2.6-s7 was a guardrail-engine change that crossed a contract boundary (engine keys ↔ onboarding chip keys) without a coordinated fix sweep.

### 3. `AllergyUncertaintyBanner` AC7 dangling across three stories
The component shipped in 3-24. The contract field (`generation_failure` on `GetPlansResponseSchema`), the audit lookup, and the route integration were each deferred — in 3-24, partially addressed in 3-25, still open after 3-29. Three stories touched it without closing the loop. Parent today sees the substitution happened but not why a slot was flagged.

### 4. Prompt-instruction vs structural-merge is pragmatic but carries test gap risk
3-23 and 3-24 both use prompt-instruction to constrain the planner (slot-scope, compound-uncertain substitution) rather than structural merge. The guardrail evaluates output so safety is preserved; non-compliance produces suboptimal not unsafe plans. But the test harness can't verify planner compliance — it only verifies guardrail evaluation. This is the accepted posture; the gap should be tracked if telemetry shows planner non-compliance.

## Key Takeaways

1. **Review sharpness is a compounding asset.** The deferred-work log used as a living in-epic reference made each successive review more informed. The deferred-work log is the right pattern; keep building on it.

2. **Cross-story contract renames need a coordinated consumer sweep.** The FALCPA synonym hole came from a guardrail-engine rename (2.6-s7) that crossed a contract boundary without sweeping all consumers. Action D4 encodes this as doctrine.

3. **Prompt-instruction vs structural-merge is a deliberate posture, not a gap — but it needs telemetry to validate.** The guardrail as safety net is correct architecture. Track planner non-compliance if it appears.

4. **Deferred refactors accumulate until forced.** `planWeek()` grew from 6 to 12 params across 6 stories. "Next time" is never. Assign it now and give it a hard deadline.

5. **Action item conditions ("when X happens") don't self-trigger.** Action #1 from Epic 2.5 retro was never done because it waited for a qualifying epic. Deadline-bound it instead.
