## 2. What went well

**The refactor-first sequencing was correct.** S1 and S2 — the two pure refactors — produced **zero real defects** between them and 2 patches total. The four behaviour-changing slices produced ~52 patches. Patch volume tracked risk, not sloppiness, and doing the safe motion first is what made the visible slices (s3, s4) cheap.

**Parity was proven, not asserted.** Unedited test suites carried the argument repeatedly: `BriefCanvas.test.tsx` 33/33 unedited through two decompositions, `DisambiguationPicker.test.tsx` ~28 its unedited through a 7-way split, `lumi.store.test.ts` additions-only (`+51/−0`), and s5's byte-identical compiled CSS (MD5 `12EE3805`) plus an exact −33/+33 test relocation count.

**Evidence discipline matured mid-epic.** S4 invented the compiled-CSS probe; s5 formalised it **with a negative control** (build *without* the glob, prove the class dies); s6 used it as dismissal evidence to kill a HIGH finding. Deliberate-violation probes (s5's lint config, s6's scheduler) became the house standard for "prove the gate actually fires."

**Reconciliations against codebase reality.** From s5 onward, stories open with a dated section correcting the build plan against what the code actually contains. This converted stale-plan risk from a mid-dev surprise into a pre-dev checklist item — the single best process invention of the epic.

**Epic 13's E2E-health work paid off measurably.** The full local suite became a trusted, load-bearing gate in all six slices. The "red is probably fine" failure mode Epic 13 identified never recurred.

## 3. What was hard

**Stale story premises — 5 of 6 slices.** s1 warned about a baseline failure fixed three weeks earlier; s3's Task 1 was already shipped in Epic 3.5; s5's plan named a `Chip` primitive that doesn't exist and an `AppHeader` that can't move; s6's plan listed five picker operations the picker never calls, and its AC2 assumed a React Query API removed in v5. **50% of all declared deviations (9 of 18) were "spec text wrong, code right"** — not developer shortcuts.

**The gates passed while real defects shipped.** In s3, s4 and s6 the review's headline find was, every time, a defect all existing gates had passed:
- **s4 (P1):** main-slot recipes could *never* load from live data — a DB CHECK forces `recipe_id` NULL on main slots. Invisible because the fixtures were contract-invalid.
- **s6:** account deletion could complete server-side **without ever calling `logout()`** — the logout lived in a `mutate()`-scoped callback React Query drops on unmount.
- **s6:** the voice-retention **privacy** toggle's rollback was a silent no-op (`setQueryData` bails on `undefined`).

**Recurring defect classes:** dead/broken Tailwind classes (4 of 6 slices), accessibility contract defects (4 of 6), tests that pass for the wrong reason (4 of 6), doc-vs-code drift (4 of 6), optimistic-update/cache races (9 findings across s4 + s6).

**Two gates cannot catch what they are invoked to protect.**
- **LHCI** collects only `http://localhost:4173/` — the unauthenticated landing route. The Brief's <2s anchor-device budget, cited in six stories' DoD, **is not measured by it**.
- **`react-hooks` ESLint** targets `**/*.{jsx,tsx}` only, so the ~8 new `.ts` hooks and slices added this epic are unlinted for rules-of-hooks (`D-14S1-2`, re-logged as `D-14S5-CR3`).
- **knip** produced zero findings in six slices — no signal either way.

**Self-implicating notes from 14-s6** (recorded because the pattern matters more than the ego): Dev Record metrics were measured with `Measure-Object -Line`, which undercounts — three figures were wrong until the Acceptance Auditor caught them. The first scheduler regression probe **passed under both schedulers**, i.e. it was exactly the placeholder-test problem the same review flagged elsewhere; the negative control caught it. And the `epic-14-retrospective: done` row was written into sprint-status before this file existed.
