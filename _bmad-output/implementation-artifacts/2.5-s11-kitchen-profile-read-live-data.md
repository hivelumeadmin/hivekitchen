### AC1 — API: `GET /v1/households/:householdId/kitchen-map` route

**New file:** `apps/api/src/modules/kitchen-map/kitchen-map.routes.ts`

```typescript
import fp from 'fastify-plugin';
import type { FastifyPluginAsync } from 'fastify';
import { z } from 'zod';
import { KitchenMapSchema } from '@hivekitchen/contracts';
import { authorize } from '../../middleware/authorize.hook.js';
import { ForbiddenError } from '../../common/errors.js';

const kitchenMapRoutesPlugin: FastifyPluginAsync = async (fastify) => {
  fastify.get(
    '/v1/households/:householdId/kitchen-map',
    {
      preHandler: authorize(['primary_parent', 'secondary_caregiver']),
      schema: {
        params: z.object({ householdId: z.string().uuid() }),
        response: { 200: KitchenMapSchema },
      },
    },
    async (request) => {
      const { householdId } = request.params as { householdId: string };
      if (householdId !== request.user.household_id) {
        throw new ForbiddenError('Cannot access another household kitchen map');
      }
      return fastify.kitchenMapService.get(householdId);
    },
  );
};

export const kitchenMapRoutes = fp(kitchenMapRoutesPlugin, { name: 'kitchen-map-routes' });
```

Register in `apps/api/src/app.ts` after the other route registrations:
```typescript
import { kitchenMapRoutes } from './modules/kitchen-map/kitchen-map.routes.js';
// ... inside buildApp, after existing route registrations:
await app.register(kitchenMapRoutes);
```

Note: `fastify.kitchenMapService` is already decorated globally via `kitchenMapPlugin` (registered before routes in `app.ts`). No additional wiring needed in the routes file.

### AC2 — Service: bump `SCHEMA_VERSION` to `'1.1.0'`

**File:** `apps/api/src/modules/kitchen-map/kitchen-map.service.ts`

The service uses `SCHEMA_VERSION` only for the Redis cache key prefix. The composer already outputs `schema_version: '1.1.0'` (since 2.5-s1). Aligning the service constant prevents unnecessary cache key mismatch confusion.

```typescript
// BEFORE:
const SCHEMA_VERSION = '1.0.0' as const;

// AFTER:
const SCHEMA_VERSION = '1.1.0' as const;
```

This is a one-line change. The cache key becomes `kitchen-map:{id}:schema-1.1.0:v{N}`. Old entries with `schema-1.0.0:v{N}` will become unreachable and expire naturally — no data loss.

#### 4c — Quote synthesis from active cultural priors

```typescript
function synthesizeQuote(cultural: KitchenMapCultural, displayName: string | null): string {
  const hard = cultural.active.filter((p) => p.enforcement === 'non_negotiable' || p.enforcement === 'strong');
  const soft = cultural.active.filter((p) => p.enforcement === 'default' || p.enforcement === 'soft');
  if (hard.length === 0 && soft.length === 0) {
    return displayName ? `${displayName}'s kitchen` : '';
  }
  const hardStr = hard.map((p) => p.label).join(', ');
  const softStr = soft.map((p) => p.label).join(', ');
  if (hardStr && softStr) return `"A ${hardStr} household with ${softStr} cooking."`;
  return `"A ${hardStr || softStr} household."`;
}
```

#### 4d — Shared tastes from household-level food preferences

```typescript
function synthesizeSharedTastes(foodPrefs: KitchenMapFoodPreference[]): string {
  const householdLoves = foodPrefs
    .filter((p) => p.child_id === null && (p.valence === 'loves' || p.valence === 'likes'))
    .map((p) => p.item);
  const householdAvoids = foodPrefs
    .filter((p) => p.child_id === null && (p.valence === 'dislikes' || p.valence === 'refuses'))
    .map((p) => p.item);
  if (householdLoves.length === 0 && householdAvoids.length === 0) return '';
  const parts: string[] = [];
  if (householdLoves.length > 0) parts.push(`Loves: ${householdLoves.join(', ')}`);
  if (householdAvoids.length > 0) parts.push(`Avoids: ${householdAvoids.join(', ')}`);
  return parts.join(' · ');
}
```

#### 4e — Bag composition pattern → human string

```typescript
const BAG_COMPOSITION_LABELS: Record<string, string> = {
  main_only: 'Main only',
  main_plus_snack: 'Main + snack',
  main_plus_extra: 'Main + extra',
  main_plus_snack_plus_extra: 'Main + snack + extra',
};

function mapBagComposition(pattern: string | null): string | null {
  if (pattern === null) return null;
  return BAG_COMPOSITION_LABELS[pattern] ?? pattern;
}
```

#### 4f — Allergens per child (from structured child_allergens table)

```typescript
function allergensByChild(allergens: KitchenMapAllergen[], childId: string): Array<{ name: string; medical: boolean }> {
  return allergens
    .filter((a) => a.child_id === childId)
    .map((a) => ({
      name: a.allergen,
      // All structured child_allergens are declared food/medical allergens.
      // Household-wide religious allergens are in household.declared_allergens — not shown here.
      medical: true,
    }));
}
```

#### 4g — Food preferences per child → loves/avoids strings

```typescript
function foodPrefsByChild(
  prefs: KitchenMapFoodPreference[],
  childId: string,
): { loves: string; avoids: string } {
  const childPrefs = prefs.filter((p) => p.child_id === childId);
  const loves = childPrefs
    .filter((p) => p.valence === 'loves' || p.valence === 'likes')
    .map((p) => p.item)
    .join(', ');
  const avoids = childPrefs
    .filter((p) => p.valence === 'dislikes' || p.valence === 'refuses')
    .map((p) => p.item)
    .join(', ');
  return { loves, avoids };
}
```

#### 4h — Child → ChildProfile shape

The `ChildProfileCard` accepts a `child` prop with interface `ChildProfile` from `mockData.ts`.  
`ChildProfile.age: number` — `KitchenMap` only carries `age_band`, not a numeric age.  
Map age_band to a representative midpoint number (dev note explains why):

```typescript
const AGE_BAND_MIDPOINT: Record<string, number> = {
  toddler: 3,
  child: 7,
  preteen: 11,
  teen: 14,
};

function mapChild(
  child: KitchenMapChild,
  allergens: KitchenMapAllergen[],
  prefs: KitchenMapFoodPreference[],
): {
  initial: string;
  name: string;
  age: number;
  ageBand: string;
  schoolBadge: string;
  meta: readonly string[];
  allergens: ReadonlyArray<{ name: string; medical: boolean }>;
  bagComposition: string | null;
  loves: string;
  avoids: string;
  lumiQuote?: string;
} {
  const { loves, avoids } = foodPrefsByChild(prefs, child.id);
  return {
    initial: child.name[0]?.toUpperCase() ?? '?',
    name: child.name,
    age: AGE_BAND_MIDPOINT[child.age_band] ?? 0,
    ageBand: child.age_band,
    schoolBadge: child.school_policies.length > 0 ? child.school_policies.join(' · ') : '',
    meta: [],
    allergens: allergensByChild(allergens, child.id),
    bagComposition: mapBagComposition(child.bag_composition_pattern),
    loves: loves || 'Not yet captured',
    avoids: avoids || 'Not yet captured',
  };
}
```

## Dev Notes

### MOCK-REF
`apps/web/src/routes/_dev-kitchen-profile.tsx` is the canonical design reference. Do NOT change it — both the dev route and the new live route coexist. The live route is a new file.

### Do NOT import from `mockData.ts` in the live route
`apps/web/src/features/kitchen-profile/data/mockData.ts` exports mock types (`EnforcedChip`, `ChildProfile`, etc.) that are tightly coupled to the Khan-Patel demo family. The live route constructs objects with matching shapes structurally — TypeScript will accept them without an explicit import of those types.

### Edit functionality is deferred — s11 is READ-ONLY
All `onSendComposite` handlers should stub to `console.log`. The `isEditing` prop is always `false`. Epic 7 (7-s1 and later) will wire editing to real API calls. Do NOT attempt to build API write endpoints for identity, children, or starting line in this slice.

### `KitchenMapChild.age_band` → `ChildProfileCard.age: number`
`KitchenMapChild` only carries `age_band: 'toddler' | 'child' | 'preteen' | 'teen'`. The `ChildProfileCard` prop interface requires `age: number` (from `ChildProfile` in mockData.ts). Use the midpoint number mapping (`toddler→3, child→7, preteen→11, teen→14`). Do NOT change `ChildProfileCard` — the component is used by the dev page too and Epic 7 will revisit it. This simplification is acceptable for s11.

### Schools and Calendar are static in s11
`SchoolsList` and `CalendarSummary` render with empty/null data. The spec explicitly defers structured schools to Epic 5 and calendar to a later slice. Use:
- Schools: `schools={[]}`, `addLabel="Add a school"`, edit handlers stubbed
- Calendar: `currentTerm={{ label: 'Current Term', value: '' }}`, `upcomingTrip={{ label: 'Upcoming Trip', value: '' }}`, `syncLabel="Sync Google Calendar"`, edit handlers stubbed

### KitchenProfilePanel (onboarding side panel) is NOT the same component
`KitchenProfilePanel` in `OnboardingText.tsx` is a real-time capture preview during onboarding. The kitchen-profile components in `apps/web/src/features/kitchen-profile/` are the post-onboarding visible memory view. These are completely separate. Do NOT confuse them.

### `fastify.kitchenMapService` is already available
`kitchenMapPlugin` is registered in `app.ts` at line 106 (`await app.register(kitchenMapPlugin)`) — before all route plugins. The `get(householdId)` method handles Redis cache reads, cache misses (recompose), and `NotFoundError` if the household doesn't exist.

### `KitchenMapSchema.meta.schema_version` is `z.literal('1.1.0')` (not `'1.0.0'`)
The service's `SCHEMA_VERSION` constant was historically `'1.0.0'` (set at slice A0.5 before 2.5-s1 bumped the schema). The composer now outputs `schema_version: '1.1.0'`. The service literal is ONLY used for the Redis cache key prefix — it does NOT validate against the schema literal. Bumping it to `'1.1.0'` (AC2) is cleanup, not a bug fix. Old `schema-1.0.0:v{N}` cache entries become unreachable and expire naturally (TTL = 1 hour).

### Role of cultural.suggested priors
`KitchenMap.cultural.suggested` priors are inferred-but-not-ratified. For the identity chip display, include them alongside `cultural.active` priors (same as the mock design). The `EnforcementChip` component will render them with appropriate visual weight based on the mapped enforcement value (`'prefer'` or `'context'`).

### `hkFetch` auto-refreshes the token on 401 — no manual handling needed
The `hkFetch` wrapper in `apps/web/src/lib/fetch.ts` handles 401 with silent token refresh and retry. The kitchen-profile page's error handler just catches all non-200 failures with a generic message.
