## What Went Well

1. **Deterministic-first cost discipline (Menon's headline).** The cost controls were built *before* the LLM feature that needed them: s8's `pickCatalogCandidate` is pure T0 (testable with no model mock) and landed before the conversational layer; s9's classifier is mini-tier; s10's chips bypass the classifier entirely; T2 regeneration only fires behind an explicit confirm tap. The cost wall is the architecture, not a budget alert. Same discipline produced better UX (confirm-then-fire = user trust) and better tests (`model:null` trace assertions, zero-call unit tests). **Pattern proven twice now (2.7, 13): deterministic core first, model at the edges, escalation behind consent.**
2. **Walls-and-gates sequencing held.** No phase started before its gate passed; the s1 baseline ran against every surface-touching slice.
3. **Convergence over addition.** The epic removed more concepts than it added — the fatigue source (route sprawl, duplicate implementations) was the target and it was hit.
4. **Epic 7 retro lesson stuck:** the cross-slice E2E ownership rule (implementing story updates the specs it breaks) was applied — s11 updated the 13-s10 spec in lockstep when `/app/plan` collapsed.

## Challenges

1. **Failing e2e tests in the Playwright UI (Menon's main pain).** Three distinct problems wearing one symptom:
   - **Full-suite SW mock bypass** (~99 local failures): the PWA service worker bypasses `page.route` mocks when the whole suite runs; reproducible, forces run-in-isolation + trust-CI workaround (memory `e2e-full-suite-sw-bypass`).
   - **Genuinely-broken baseline test:** 13-s1's `"edit tuesday"` positive control asserts a `role="group"` that never existed (failed since `f3130e6`); every slice since paid a git-stash toll to re-prove "pre-existing."
   - **Four obsoleted specs** (3-14, 3-15, 3-25, 3-27) exercising the deleted `/app/plan`, still red in the runner.
2. **Review patch volume front-loaded on surface rebuilds:** s5 took 14 patches (incl. 2 safety-display issues the s1 gate didn't catch — caught by adversarial review instead); s7 took 5; s11 took 2. Partly the review doing its job on the riskiest slices, but the safety-display class deserves gate coverage.
3. **Status bookkeeping drift:** s2.5 sat `in-progress` after shipping (corrected at this retro).
4. **Scratch-script accumulation:** ~15 untracked `apps/api/_*.mjs` helpers in the working tree.

## Key Insights

1. A regression gate with a permanently-red entry trains "red = probably fine" — the exact failure mode a gate exists to prevent. Gates must be fully green or the red is load-bearing noise.
2. Heavy review-patch counts on rebuild slices are a *risk signal to plan around* (schedule adversarial review early), not a process failure.
3. The deterministic-first pattern is now a house style; new agentic features should be spec'd with the T0/mini/T2 tier split from day one.
