## Story

As a **household onboarding through Moment 5 when Lumi lacks confidence for one or more of my declared cuisine buckets**,
I want **Lumi to acknowledge the limitation and ask me directly what my family eats**,
so that **I never see a sparse or stereotyped chip card that undermines trust at the most critical first-impression moment of onboarding**.

Cold-start mode replaces the chip card with a single conversational prompt: *"I want to make sure I get this right — tell me three dishes your family eats most weeks."* The parent types freely; each response is declared directly to the catalog. The finalize gate relaxes to ≥3 declared items.

---

## Context & Trigger Conditions

Cold-start fires when `CatalogProjectionService.getM5Chips()` detects any of the three named conditions:

| Reason | Meaning |
|---|---|
| `per_cuisine_floor` | Stage 1 completed, but for at least one declared cuisine bucket, fewer than 5 catalog-seeded recipes are available. Fires even if the Anglo bucket is full — *the weak bucket is the signal.* |
| `stage1_timeout` | Stage 1 has not emitted a `stage1_completed_at` timestamp within 5s of M5 entry, AND after the fall-through, per-cuisine check confirms below-floor counts. |
| `stage2_terminal` | Stage 2 ran but left zero catalog-seeded items for the household — total catalog count = 0 after recovery. |

Cold-start is **first-impression only**. Once triggered, it is persisted and NOT retroactively exited post-M5 if Stage 1/2 subsequently re-runs and produces better results.

### AC3 — Per-cuisine floor check in `getM5Chips`

After the diversity cap step (Step 6 in the existing pipeline), add a per-cuisine floor check:

```
PER_CUISINE_FLOOR_THRESHOLD = 5
```

Algorithm (applied to the raw `rows` from Step 2, not the diversity-capped set):
1. For each tag in `declaredCuisineTags`, count how many rows in `rows` have `cuisine_tags` containing that tag.
2. If ANY declared cuisine bucket has count `< PER_CUISINE_FLOOR_THRESHOLD` → cold-start fires.

If cold-start fires, determine reason:
- `timedOut === true` → `'stage1_timeout'`
- `rows.length === 0` (total catalog empty) → `'stage2_terminal'`
- Otherwise → `'per_cuisine_floor'`

Log the cold-start reason before returning:
```ts
this.logger.info({
  module: 'catalog',
  action: 'catalog.m5.cold_start_triggered',
  household_id: householdId,
  cold_start_reason: reason,
  declared_cuisine_count: declaredCuisineTags.length,
  total_catalog_rows: rows.length,
}, 'M5 cold-start triggered');
```

Return `{ chips: [], coldStartReason: reason }` — chips are always empty in cold-start mode (never render a partial chip card alongside the conversational prompt).

**Fills `// TODO(2.6-s6): route to cold-start fallback when below_threshold fires` (catalog-projection.service.ts line 131).**

When `declaredCuisineTags` is empty (household has no M3-declared cuisine priors), the per-cuisine check cannot fire — cold-start via this check is skipped. `stage1_timeout` and `stage2_terminal` can still trigger (via timeout or zero rows). If `declaredCuisineTags.length === 0` and rows exist and no timeout → return chips normally with `coldStartReason: null`.

### AC9 — Override-fewer chip injection threshold adjusted for cold-start

The override-fewer chip currently injects when `favoriteLunchCount >= 4`. In cold-start mode the threshold drops to `>= 1` (override floor is 1 declared item). Adjust the injection guard:

```ts
const overrideThreshold = coldStartTriggered ? 1 : 4;

if (
  nextCurrentMoment === 'm5_starting_line' &&
  favoriteLunchCount >= overrideThreshold &&
  chip_config !== null &&
  chip_config.mode === 'choice' &&
  chip_config.options !== undefined
) {
  chip_config = {
    ...chip_config,
    options: [...chip_config.options, { key: 'override_fewer', label: 'Start with fewer' }],
  };
}
```

In cold-start mode, `chip_config` will be `null` (no chips), so the override-fewer injection block will never fire even with the relaxed threshold — this is correct. The override chip is not shown alongside the conversational prompt; override happens when the parent taps the Send button with fewer than 3 declared items (server-side AC8 handles the count gate).

If `coldStartTriggered` is true and `favoriteLunchCount >= 1` and the agent emits `[NEXT_MOMENT:summary]` (because the parent forced it via text), the `m5OverridePath` check fires normally — no new logic needed.

## Edge Cases (from brief rev 3, §2.6-s6)

### Mixed-confidence cohorts
Parent declares `['english', 'tibetan']` at M3. Stage 1 produces 22 English items, 2 Tibetan items. Per-cuisine threshold fires (`tibetan < 5`). Parent gets the conversational prompt — NOT a mixed card with 22 Anglo chips + 2 Tibetan chips. This is intentional per UX spec and brief. Documented in AC3.

### Override in cold-start branch
Cold-start threshold = 3. Override-fewer chip appears at ≥ 1 item (not ≥ 4). Floor is 1: parent must declare at least 1 item to finalize; with 0 items the Send button is disabled (client-side) and the server gate rejects finalize with a ConflictError. If parent supplies exactly 1 or 2 items and takes override, `m5_complete` is set true via `m5OverridePath` logic (parent moved from `m5_starting_line` to `summary` with count ≥ override floor). `cold_start_under_floor` telemetry fires at finalize.

### Cold-start not retroactively re-entered
If parent navigates back to M2 and changes allergens, triggering Stage 1 + Stage 2 re-run, and the new recovery produces a strong per-cuisine count: `cold_start_triggered` flag persisted in `onboarding_moment_state` is **never reset to false** by this service. Existing `declared` rows are preserved; if the parent returns to M5 they may now see chip_config populated (since the catalog improved) — but `cold_start_triggered` flag stays true for telemetry. Cold-start was a real first-impression event; the flag captures it happened, not the current catalog state.

### stage1_timeout + healthy catalog
If Stage 1 timed out but Stage 0 had already seeded a healthy per-cuisine baseline (≥5 for all declared buckets), cold-start does NOT fire. The timeout alone is not sufficient — the per-cuisine count must also be below floor. See AC3 algorithm.

### No declared cuisine priors (M3 skipped)
`declaredCuisineTags` is empty. Per-cuisine check skips. Cold-start can only fire via `stage2_terminal` (zero rows total). `stage1_timeout` alone with non-empty catalog does not trigger cold-start. This is correct: a parent who skipped M3 gets the best chip card we can assemble from the Stage 0 global baseline.
