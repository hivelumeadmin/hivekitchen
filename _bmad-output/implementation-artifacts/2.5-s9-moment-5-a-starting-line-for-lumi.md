## Story

As a parent completing the Moment 5 ("A starting line for Lumi") step of onboarding,
I want Lumi to present multi-select lunch item chips plus a free-text input with a count indicator,
so that Lumi can record ≥10 household favorite lunches as the cold-start seed (FR124) and use them to generate the first personalized plan.

### FavoriteLunchesRepository — Upsert Pattern

Unlike `FoodPreferencesRepository` (which uses a functional unique index and needs the 42P10 fallback), `favorite_lunches` has a standard composite unique index:

```sql
CREATE UNIQUE INDEX favorite_lunches_household_hash_uniq
  ON favorite_lunches (household_id, item_hash);
```

No NULL columns in the index → no functional index → no 42P10 error possible. Use standard Supabase upsert:

```typescript
const { data, error } = await this.client
  .from('favorite_lunches')
  .upsert(
    { household_id, item: ciphertext, item_hash, provenance: 'onboarding_seed', position: resolvedPosition },
    { onConflict: 'household_id,item_hash', ignoreDuplicates: true }
  )
  .select('id, position')
  .maybeSingle();

if (data !== null) return { id: data.id, position: data.position };

// Conflict: existing row — fetch it
const { data: existing } = await this.client
  .from('favorite_lunches')
  .select('id, position')
  .eq('household_id', household_id)
  .eq('item_hash', item_hash)
  .single();
return { id: existing.id, position: existing.position };
```

### Position Auto-Increment

When `position` is not provided by the caller:

```typescript
const { data: maxRow } = await this.client
  .from('favorite_lunches')
  .select('position')
  .eq('household_id', householdId)
  .order('position', { ascending: false })
  .limit(1)
  .maybeSingle();

const resolvedPosition = maxRow !== null ? maxRow.position + 1 : 0;
```

### OnboardingText.tsx — Follow M4 Pattern Exactly

M4 (`m4BagCapture`) is the template. M5 (`m5StartingLine`) follows the same lifecycle:
- `useState<M5StartingLineState>({ state: 'none' })`
- `useEffect` for `'none'` → `'capturing'` (watches `currentMomentKey === 'm5_starting_line'`)
- `submitTurn` drives `'capturing'` → `'captured'` on NEXT_MOMENT advance

M5 differs from M4 in two ways:
1. `capturing` state carries a `count: number` (accumulated chip count per turn)
2. `captured` state carries `overridden: boolean`

The count tracking in `submitTurn` must happen BEFORE the POST (optimistic) so the card feels responsive. If the POST fails and state is rolled back, also roll back `m5StartingLine`.

### Previous Story Learnings (from 2.5-s8)

- **Encryption is REQUIRED for `item`** — `favorite_lunches.item` is AES-256-GCM ciphertext per the migration comment. Use `encryptField` + `getOrCreateHouseholdDek` exactly like `FoodPreferencesRepository`.
- **No 42P10 fallback** — `favorite_lunches` has a simple composite unique index, not a functional index. The fallback pattern from `food-preferences` and `dietary-preferences` does NOT apply here.
- **Cross-household guard not needed for favorite_lunches** — it's household-scoped by primary key (`household_id`); no per-child ownership guard required.
- **Insert column must exist in SELECT** — verify `position` is returned from the upsert `.select('id, position')` call; confirm column exists (migration: `position integer NOT NULL DEFAULT 0`).
- **Provenance** — always `'onboarding_seed'` for this tool. Do NOT accept provenance from the agent — it's an internal concern.
- **IcoSeed SVG** — already authored in `Moment5Page.tsx` lines 69–75; copy the inline function, do not import from mockup file.
- **M5 profile card uses `IcoSeed`, NOT `IcoLunchBag`** — `IcoLunchBag` is M4's icon.
- **Override chip is NOT a lunch item** — when `chip_selections` contains `override_fewer`, the agent must NOT call `favorite_lunch.add` for it. The lookup table in the prompt explicitly calls this out.
- **Parallel tool inference** — when 5 chips are selected, the agent fires 5 concurrent `favorite_lunch.add` calls. The repository handles each independently. No ordering guarantee needed since we compute `MAX(position) + 1` per-call (positions may have gaps under concurrency — that's acceptable).
- **M5 count is session-only in the UI** — `OnboardingText.tsx` tracks chips submitted in the current session for the profile card. The true count lives in the DB (read in 2.5-s11). No attempt to reconcile with prior sessions on mount.
- **`onboarding.tools.test.ts` pre-existing failures** — 5 tests in this file fail due to missing `resolveAllergen`/`isActive` mock stubs (pre-existing, documented in 2.5-s8). Verify your new test passes; do not fix the pre-existing failures.
