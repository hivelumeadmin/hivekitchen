## Dev Notes

### Why this slice exists

Epic 2.7 inverts onboarding's control flow (slices `s6`/`s7`): a deterministic controller takes over the FSM and a pile of service-side safety nets is deleted. That is the riskiest change in the epic. The planner re-architecture (Epic 3.5) de-risked its equivalent (the single-shot loop collapse, 3.5-s5) by building a golden-set eval FIRST (3.5-s1) and keeping it green through every change. This slice ports that discipline. Built first, the eval captures the behavior contract *before* anything changes, so later slices are proven against recorded behavior, not a written spec.

### The determinism constraint (critical)

Onboarding turns produce non-deterministic conversational prose, so a byte-stable eval can only assert **structured outcomes**: moment transitions, slot fills (resulting Kitchen Map state), and tool calls. The harness replays **recorded/mocked LLM responses** per scenario so the structured outcomes are deterministic. Never assert the assistant's wording — later slices (especially `s5` chip templates and `s7` prompt changes) will legitimately change prose, and an eval that pins prose would produce false failures.

### Patterns to follow

- **Planner golden eval (3.5-s1)** is the structural template: `apps/api/src/agents/eval/` + the golden test. Match its fixture/runner/CI shape so the two evals are symmetric.
- **`onboarding.agent.test.ts`** already mocks the OpenAI client for the tool loop (single tool, parallel tools, error-as-JSON recovery, `[SESSION_COMPLETE]`). Reuse that mocking approach for the per-turn replay.
- **`onboarding.service.test.ts`** already drives `submitTextTurn` with test doubles for the moment FSM, required-set gate, finalize, resume/reset. Reuse those doubles for the harness.

### Anti-patterns to avoid

- **Do not** assert assistant prose or token-level output — structured outcomes only.
- **Do not** make live OpenAI calls — replay recorded responses.
- **Do not** change any production code in this slice. It is additive test infrastructure; if you find a bug while capturing the baseline, log it, do not fix it here (it would change the baseline the later slices must preserve).
- **Do not** skip the safety-net scenarios (AC5) — they are the exact behaviors `s6`/`s7` must be proven to preserve when the safety nets are deleted.
