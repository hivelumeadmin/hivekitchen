## Story

As **the onboarding conversation system**,
I want **the OnboardingAgent's text-mode prompt to be fully replaced with a v2 chaptered conversation prompt that understands the 5-moment structure, all 11 tools, chip turn inputs, skip behaviour, and the required-set completion gate — and for all 11 tools to be exposed to the agent** —
so that **every downstream moment slice (2.5-s5 through 2.5-s9) can wire its specific content against an agent that already knows how to navigate moments, fire tools in parallel, read chip selections, and refuse premature finalization** — and so that `onboarding_moment_state.current_moment` and `required_set_status` are tracked accurately after each turn.

**New `ONBOARDING_CORE_TEXT_V2` constant** (replaces `ONBOARDING_CORE_TEXT` as what `getOnboardingSystemPrompt('text')` returns). Content requirements:

**Chaptered conversation structure (5 moments + summary):**
```
Moment 1 — "Who's at the table"
  Required: household display_name, ≥1 child with name + age_band
  Tools: household.set_name, child.upsert (one call per child)
  Chips: hint chips (broad question — Lumi suggests example family patterns; no selection required)
  Skip: Not skippable (required set)

Moment 2 — "What I need to keep safe"
  Required: explicit allergen response for every child (declare allergens OR confirm no known allergens)
  Tools: allergen.declare (one call per allergen per child), child.upsert (patch-only if needed)
  Chips: action chips (allergen vocabulary) + "No known allergens" sentinel chip per child
  Skip: Not skippable (safety wall — required set)

Moment 3 — "How your kitchen tastes"
  Optional: cultural + religious identity, dietary preferences, cuisine, food preferences
  Tools: cultural.note, cuisine.declare, dietary.declare, food_preference.declare, household.upsert, rule.set
  Chips: choice chips (multi-select cuisine/dietary; single-select enforcement elevation)
  Skip: Skippable — "Skip this moment" chip is available

Moment 4 — "What goes in the bag"
  Optional: bag composition pattern per child
  Tools: child.upsert (with bag_composition_pattern)
  Chips: action chips (pattern options) per child
  Skip: Skippable — "Skip this moment" chip is available

Moment 5 — "A starting line for Lumi"
  Required: ≥10 favourite lunches declared
  Tools: favorite_lunch.add (one call per item)
  Chips: choice chips (multi-select lunch items from a common list)
  Skip: Not skippable (required set); "Override" chip available when count ≥6 for early finalize
  
Summary — Review and finalize
  The agent reads back what was captured. Hard-elevation chips appear per-item for any cultural/dietary
  signal the household elevated to 'strong' or higher. Finalize transitions is_onboarded=true.
  Required: required_set_complete = true before finalize is allowed.
```

**Current-moment awareness:**
A system block injected before the conversation history (see AC4) tells the agent:
```
CURRENT ONBOARDING STATE
current_moment: <value from onboarding_moment_state.current_moment>
required_set:
  m1_household_name: true/false
  m1_child_declared: true/false
  m2_allergen_response: true/false   (true = at least one child's allergen status explicitly stated)
  m5_favorite_count: 0–N
  m5_complete: true/false            (true when m5_favorite_count >= 10)
required_set_complete: true/false
```

The prompt instructs the agent:
- Work within `current_moment` until its exit condition is met (required fields set, or skip signal received)
- When `current_moment` is `pre_start`, start with Moment 1 ("Who's at the table")
- After completing a moment's required work, transition to the next moment naturally in your prose
- Embed a moment-advance directive at the END of your response (see AC1.1 below)

**AC1.1 — Moment-advance directive:**

When the agent decides to advance to the next moment (or skip), it embeds exactly this at the **end of its prose response**, before any trailing whitespace:

```
[NEXT_MOMENT:<moment_key>]
```

Valid values: `m1_table`, `m2_safe`, `m3_taste`, `m4_bag`, `m5_starting_line`, `summary`, `finalized`.

Examples:
- After collecting household name + first child → `[NEXT_MOMENT:m2_safe]`
- After M2 allergen response confirmed → `[NEXT_MOMENT:m3_taste]`
- When user taps M3 skip chip → `[NEXT_MOMENT:m4_bag]`
- After M5 favorites count ≥ 10 → `[NEXT_MOMENT:summary]`

The service strips this directive from the prose before persisting (see AC5). The directive is invisible to the user. If the agent forgets to emit the directive, the service keeps `current_moment` unchanged (safe fallback — next turn will re-read the same moment and continue).

**Chip turn understanding:**

The prompt must include:
```
When the user's message starts with [Chips selected: ...], the parent chose from the chip options 
Lumi provided. Treat the comma-separated chip keys as explicit declarations — each key is a 
structured choice (e.g. "peanut" = allergen.declare, "south_indian" = cuisine.declare).
Fire the appropriate tool for each chip key AS WELL AS for any free-text the parent added.

When [Chips selected: skip] appears, the parent is skipping the current good-to-have moment.
Acknowledge warmly ("Of course, we can fill that in anytime") and embed [NEXT_MOMENT:<next>].

When [Chips selected: no_known_allergens] appears for a child, treat it as an explicit "no allergens"
declaration for that child. Set m2_allergen_response = true for that child. No allergen.declare call.
```

**Multi-tool parallel inference:**

The prompt must explicitly instruct: "Fire all relevant tool calls in a single response turn — do not wait for one tool's result before deciding to call another. For example, if a parent names three allergens for two children, emit six allergen.declare calls in the same turn. Tools are batched and run concurrently by the runtime."

**Required-set gate / finalize behaviour:**

```
You MAY NOT emit [NEXT_MOMENT:summary] until:
  required_set_complete = true
  (meaning: m1_household_name, m1_child_declared, m2_allergen_response, and m5_complete are all true)

If the parent tries to end the conversation before required_set_complete = true, acknowledge warmly and
guide them to the remaining required moment(s). Never refuse rudely — Lumi is helpful, not bureaucratic.

Example refusal: "Almost there! We still need to cover [what's missing]. Let me ask you about that."
```

**Anti-narration discipline (extended to moments):**

The existing rule "Don't narrate tool calls" extends: "Don't announce that you're entering a new moment. Don't say 'Now let's move to Moment 2.' Transition naturally: ask the next topic's question in warm prose and embed [NEXT_MOMENT:...] silently at the end."

**`TEXT_RULES` updated (in-place):**

Add: "Never emit `[NEXT_MOMENT:...]` or other directives without the surrounding square brackets — the service strips them by regex. Never emit a directive mid-response; always at the very end of your prose."

### AC4 — Moment state injection into agent context

`OnboardingAgent` (`apps/api/src/agents/onboarding.agent.ts`) gains a new optional field in `RespondOptions`:

```typescript
export interface RespondOptions {
  modality?: OnboardingModality;
  tools?: ToolSpec[];
  kitchenMapBlock?: string;
  vocabularyBlock?: string;
  momentStateBlock?: string;  // NEW — injected after kitchen map block

```

In the agent's `respond()` method, when `momentStateBlock` is present, it is concatenated into the system prompt **between `kitchenMapBlock` and `vocabularyBlock`** (or appended after the kitchen map block if vocabularyBlock is absent). The ordering in the system message:

```
1. [ONBOARDING_CORE_TEXT_V2]
2. [TEXT_RULES]
3. [kitchenMapBlock]        ← stable prefix; OpenAI cache-friendly
4. [momentStateBlock]       ← NEW: current moment + required_set_status
5. [vocabularyBlock]        ← semi-stable; tags change rarely
```

The `renderMomentStateBlock(state: MomentState | null): string` function lives in `apps/api/src/modules/onboarding/onboarding.service.ts`:

```typescript
function renderMomentStateBlock(state: MomentState | null): string {
  if (state === null) {
    return `CURRENT ONBOARDING STATE
current_moment: pre_start
required_set:
  m1_household_name: false
  m1_child_declared: false
  m2_allergen_response: false
  m5_favorite_count: 0
  m5_complete: false
required_set_complete: false`;
  }
  const rss = state.required_set_status;
  const complete =
    rss.m1_household_name &&
    rss.m1_child_declared &&
    rss.m2_allergen_response &&
    rss.m5_complete;
  return `CURRENT ONBOARDING STATE
current_moment: ${state.current_moment}
required_set:
  m1_household_name: ${rss.m1_household_name}
  m1_child_declared: ${rss.m1_child_declared}
  m2_allergen_response: ${rss.m2_allergen_response}
  m5_favorite_count: ${rss.m5_favorite_count}
  m5_complete: ${rss.m5_complete}
required_set_complete: ${complete}`;
}
```

### AC5 — Post-turn moment state update in `OnboardingService`

`OnboardingService.submitTextTurn()` gains two new phases:

**Phase A — pre-turn (before agent call):**

```typescript
// Read current moment state; pass to agent context
const momentState = await this.momentRepository.getState(input.householdId);
// ...
const reply = await this.agent.respond(agentInput, {
  modality: TEXT_MODALITY,
  tools: toolSpecs,
  kitchenMapBlock: renderKitchenMapBlock(map),
  momentStateBlock: renderMomentStateBlock(momentState),
  vocabularyBlock: renderVocabularyBlock(this.vocabularyService),
});
```

**Phase B — post-turn (after agent text is received, before persisting Lumi's turn):**

1. **Strip the `[NEXT_MOMENT:...]` directive** from the agent's prose:
   ```typescript
   const NEXT_MOMENT_RE = /\[NEXT_MOMENT:([a-z0-9_]+)\]\s*$/;
   const match = lumiText.match(NEXT_MOMENT_RE);
   const nextMoment = match ? match[1] : null;
   const cleanedLumiText = lumiText.replace(NEXT_MOMENT_RE, '').trimEnd();
   ```
   Use `cleanedLumiText` everywhere from this point (persist, return, sanitize).

2. **Compute `required_set_status` from DB** (call a private method `computeRequiredSetStatus`):
   ```typescript
   private async computeRequiredSetStatus(householdId: string): Promise<RequiredSetStatus> {
     // Query household.display_name IS NOT NULL AND != ''
     // Count children rows for household
     // Count child_allergens rows OR check m2_allergen_response flag in current state
     // Count favorite_lunches rows for household
   }
   ```
   
   For `m2_allergen_response`: this is `true` when:
   - COUNT(`child_allergens`) > 0 for this household, OR
   - The `required_set_status.m2_allergen_response` in the current DB state is already `true`
   
   The second condition handles the "no known allergens" case: when a user selects the sentinel `no_known_allergens` chip for all children, the agent receives `[Chips selected: no_known_allergens]` and the prompt instructs it NOT to call `allergen.declare`. Instead, the service must still mark `m2_allergen_response = true`. The mechanism: the prompt instructs the agent to write `[NEXT_MOMENT:m3_taste]` when the user selects no_known_allergens (advancing out of M2), and the service sets `m2_allergen_response = true` whenever it advances past M2.
   
   **Simpler rule:** `m2_allergen_response = true` if:
   - `nextMoment` is NOT `m2_safe` AND current `current_moment` was `m2_safe` (meaning the agent advanced OUT of M2 this turn), OR
   - COUNT(`child_allergens`) > 0 for this household, OR
   - the existing DB `required_set_status.m2_allergen_response` is already `true`

3. **Compute `nextCurrentMoment`:**
   ```typescript
   const nextCurrentMoment = nextMoment ?? momentState?.current_moment ?? 'm1_table';
   ```
   If the agent didn't emit a directive AND there's no existing state, default to `m1_table` (first turn).

4. **Upsert `onboarding_moment_state`:**
   ```typescript
   await this.momentRepository.upsertState(input.householdId, {
     current_moment: nextCurrentMoment,
     required_set_status: computedRss,
   });
   ```

5. **Compute `chip_config` from `nextCurrentMoment`:**
   ```typescript
   const chip_config = momentToChipConfig(nextCurrentMoment);
   ```
   Function `momentToChipConfig` maps moment keys to chip configs. In this slice, ALL moments return `null` — the actual chip configs are wired in s5 through s9.

6. **Return `chip_config` in result:**
   ```typescript
   // In SubmitTextTurnResult:
   chip_config: ChipConfig | null;
   ```

### AC9 — Prompt v2 tooling guidance: all 11 tools documented

The prompt must include a tools section that documents all 11 tools. The 4 existing tools are already documented in the v1 prompt (rephrase for v2 moment context). The 7 new tools need clear guidance:

| Tool | When to call | Key constraint |
|---|---|---|
| `household.set_name` | M1 — when parent names the household | One call total per onboarding |
| `allergen.declare` | M2 — one call per allergen per child | One allergen per call; never batch into an array |
| `dietary.declare` | M3 — when parent states dietary law/identity (halal, vegan, etc.) | Pass `enforcement` based on stated strength |
| `cuisine.declare` | M3 — when parent names a cuisine tradition ("we cook south Indian") | Use `confidence` + `presence` estimates |
| `food_preference.declare` | M3 — item-level likes/dislikes/refuses | `valence` enum: loves/likes/neutral/dislikes/refuses |
| `favorite_lunch.add` | M5 — one call per lunch item | Items are household-scoped; target 10 items |
| `rule.set` | M3 or M2 — household-wide rules (no pork, no beef, etc.) | `enforcement` defaults to 'strong' |

In addition: `household.upsert` and `child.upsert` continue to be available throughout all moments.

The prompt must clarify the routing between tools:
- **allergen vs food_preference:** medical allergens → `allergen.declare`. "Hates X" / "won't eat X" → `food_preference.declare(valence='refuses')`.
- **cultural.note vs cuisine.declare:** cultural identity ("we're a Hindu family") → `cultural.note`. Cuisine practice ("we cook biryani every Friday") → `cuisine.declare` or `memory.note(node_type='rhythm')`.
- **household.upsert vs dietary.declare:** the old `household.upsert(dietary_preferences=[...])` path still works for compatibility. New structured path: `dietary.declare`. Use `dietary.declare` in v2 for new declarations; `household.upsert` for corrections to existing fields.

## Dev Notes

### Moment-advance directive: placement and regex

The directive `[NEXT_MOMENT:<key>]` must appear at the very end of the agent's prose response. The stripping regex:

```typescript
const NEXT_MOMENT_RE = /\[NEXT_MOMENT:([a-z0-9_]+)\]\s*$/;
```

Apply this regex BEFORE `stripExpressionTags()` so the two operations don't interfere. The sequence in the service:

```typescript
const raw = reply.text;
const directiveMatch = raw.match(NEXT_MOMENT_RE);
const nextMoment: string | null = directiveMatch ? directiveMatch[1] : null;
const withoutDirective = raw.replace(NEXT_MOMENT_RE, '').trimEnd();
const sanitizedLumiText = stripExpressionTags(withoutDirective);
// ... persist sanitizedLumiText
```

### `computeRequiredSetStatus`: keep it read-only and fast

The method reads from:
1. `households` table: `display_name IS NOT NULL AND display_name != ''`
2. `children` table: `COUNT(*) > 0 WHERE household_id = $1`
3. `child_allergens` table: `COUNT(*) > 0 WHERE household_id = $1`
4. `favorite_lunches` table: `COUNT(*)`

These are four lightweight COUNT queries. The repository can run them in parallel via `Promise.all`. Total latency budget: ~40ms.

The `m2_allergen_response` logic (from AC5):
```typescript
const m2_allergen_response =
  (child_allergens_count > 0) ||
  (momentState?.required_set_status.m2_allergen_response === true) ||
  (nextMoment !== null && nextMoment !== 'm2_safe' && currentMoment === 'm2_safe');
```

The third condition catches the "no known allergens" flow: the agent advances out of m2_safe even with no allergen rows written.

### Supabase client import in `OnboardingMomentRepository`

The `OnboardingMomentRepository` receives a `SupabaseClient` (from `@supabase/supabase-js`) injected via its constructor. Pattern matches `CulturalPriorRepository` — import `type { SupabaseClient } from '@supabase/supabase-js'`. The constructor stores it as a private readonly field.

The upsert query:
```sql
INSERT INTO onboarding_moment_state (household_id, current_moment, required_set_status)
VALUES ($1, $2, $3)
ON CONFLICT (household_id)
DO UPDATE SET
  current_moment = EXCLUDED.current_moment,
  required_set_status = EXCLUDED.required_set_status,
  updated_at = now();
```

Via supabase-js:
```typescript
const { error } = await this.supabase
  .from('onboarding_moment_state')
  .upsert({
    household_id: householdId,
    current_moment: state.current_moment,
    required_set_status: state.required_set_status,
  }, { onConflict: 'household_id' });
```

### Prompt v2 length and cache discipline

The v2 prompt is substantially longer than v1 (5 moments × tool documentation + state-awareness instructions ≈ 1200–1800 tokens). The kitchenMapBlock and vocabularyBlock are the stable prefix that benefits from OpenAI's auto-prefix cache; the momentStateBlock changes each turn (current_moment changes). Keep momentStateBlock AFTER kitchenMapBlock + vocabularyBlock in cache ordering would be ideal, but the current implementation places it between the two. This is acceptable since the state block is small (~15 lines) and doesn't break cache for the larger stable prefix.

If cache performance becomes a concern post-s4, the ordering can be adjusted (kitchenMap → vocabulary → momentState), but this is a future optimization.
