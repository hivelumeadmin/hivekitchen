## Challenges

### Spec snippet-to-reality gap (~3 reconciliations/story average)
Stories were authored before the implementing developer touched the code. Almost every story had 2–8 places where the spec snippet didn't match the actual codebase state. Recurring examples:

- **hkFetch already JSON.stringifies** — story snippets that passed `JSON.stringify(body)` would double-encode (hit in 7-s3 and others)
- **Zod 4 `z.record()` requires two-arg form** — one-arg form throws; hit in 7-s9
- **Zod 4 `.uuid()` strict RFC-4122** — non-standard variant nibble in fixtures causes rejection (7-s9 fixture used `…-4444-…` instead of `…-8444-…`)
- **Zod 4 `.datetime()` rejects Supabase offset timestamps** — normalize with `new Date(ts).toISOString()` (7-s17)
- **ChildrenRepository is a 4-arg constructor** — story snippet had 2 args (7-s10)
- **BullMQ scheduler API** — `getQueue(Q).upsertJobScheduler(...)` not `fastify.bullmq.upsertJobScheduler(...)` (7-s11)

This is not a developer quality issue — it's a documentation lag between story authoring time and implementation time. The codebase evolves; snippets fossilize.

### Cross-slice E2E coupling (7-s2/7-s3/7-s4)
The 7-s2 E2E spec (`7-s2-provenance-chips.spec.ts`) was touched by three different stories:
- 7-s2: authored (all three pills disabled)
- 7-s3: updated (Edit pill enabled — "three disabled" assertion broken)
- 7-s4: updated again (Forget pill enabled + `forget_reason: null` added to shared fixture)

Any developer implementing a later slice must know which earlier E2E tests their changes will break. This wasn't always obvious from the story.

### USER-SIDE GATE sequence (6 migrations, no aggregate runbook)

## Key Insights

1. **The `runXxx(deps)` extraction pattern for BullMQ jobs should be a project standard.** Document it in project-context or the job template so future stories don't debate it.

2. **Zod 4 known gotchas need a shared reference.** The same three quirks (`z.record` two-arg, `.uuid()` strict variant, `.datetime()` offset rejection) bit multiple stories. A project-context entry would eliminate future reconciliation cost.

3. **The `hkFetch` double-encoding trap needs a comment at the source.** `apps/web/src/lib/fetch.ts` should note that `init.body` is JSON.stringified internally — passing a pre-stringified value double-encodes it.

4. **Cross-slice E2E ownership should be explicit in the story template.** When a story's implementation will break a previous story's E2E assertions, the implementing story owns those updates. This needs to be a stated expectation, not tribal knowledge.

5. **"Built but unused" primitives are a valid and clean delivery pattern.** 7-s12 and 7-s13 proved this works — ship the scaffold, wire the caller in the epic that needs it.
